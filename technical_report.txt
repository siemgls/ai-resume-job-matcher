AI Resume–Job Matching System
Introduction

The goal of this project is to develop an AI-powered system that evaluates how well a resume matches a job description. Resume screening is a common challenge in recruitment, where companies must efficiently identify candidates whose skills and experience align with job requirements.

This project approaches the problem using Natural Language Processing (NLP), transformer-based semantic similarity models, and AI-generated feedback. Instead of relying only on keyword matching, the system compares the semantic meaning of resumes and job descriptions to better understand candidate relevance.

The application also includes:

AI-based skill extraction
Missing skill detection
Experience matching
Personalized resume improvement suggestions
Skill gap roadmap generation
Automatic job recommendation across multiple jobs

The complete implementation is available in the project GitHub repository.

Data

Because large labeled resume–job matching datasets are not publicly available, a custom dataset was created for experimentation and evaluation.

The dataset contains resume and job description pairs labeled as:

1 = good match
0 = poor match

The dataset includes approximately 30 manually created examples covering multiple domains such as:

Software Engineering
Data Science
Business
Design
Marketing

Basic preprocessing steps included:

Lowercasing text
Removing extra whitespace
Cleaning inconsistent formatting

For the automatic job recommendation functionality, additional job description datasets were used and cleaned for semantic retrieval and matching.

One challenge encountered was the relatively small dataset size, which limits generalization and evaluation reliability.

Model & Methods

The system uses transformer-based sentence embeddings from the Sentence Transformers library.

Base Model
all-MiniLM-L6-v2

This model converts resumes and job descriptions into dense vector embeddings that capture semantic meaning.

The system combines several scoring components:

1. Semantic Similarity

Semantic similarity is calculated using cosine similarity between:

Resume embeddings
Job description embeddings

This allows the system to understand contextual similarity rather than relying only on exact keywords.

2. Skill Matching

The application extracts relevant technical and professional skills from:

The resume
The job description

The system then:

Identifies matched skills
Detects missing skills
Computes a skill overlap score
3. Experience Matching

A lightweight experience extraction module detects years of experience mentioned in:

Resumes
Job descriptions

The system compares:

Candidate experience
Required experience

and produces an experience compatibility score.

4. Final Weighted Scoring

The final match score is computed using a weighted combination of:

Component	Weight
Semantic Similarity	50%
Skill Matching	35%
Experience Matching	15%

This hybrid approach provides more balanced scoring than using semantic similarity alone.

5. Fast Semantic Retrieval

To improve performance, precomputed job embeddings are used for fast semantic job search.

Instead of fully analyzing hundreds of jobs one by one:

The system first retrieves the most semantically similar jobs
Detailed scoring is then applied only to the top candidates

This significantly improves scalability and responsiveness.

6. AI Feedback & Resume Improvement

The system integrates GPT-based feedback generation using the OpenAI API.

Features include:

Resume strengths analysis
Weakness detection
Personalized improvement suggestions
Resume rewriting recommendations
Skill gap learning roadmap generation

This transforms the project from a scoring tool into an interactive career-assistance platform.

Challenges & Future Work
Challenges

The largest challenge was the lack of a large, publicly available labeled dataset for resume–job matching. This required manually creating training and evaluation examples.

Another challenge was balancing:

Performance
Accuracy
Computational efficiency

This led to the use of a lightweight transformer model (MiniLM) instead of larger embedding models.

Handling Streamlit state management and optimizing semantic search performance were also important implementation challenges.
